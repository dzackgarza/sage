# GAP finite matrix-group order/recognition for the LORENTZ image-order nodes

Status: capability measured in a sandbox over the published image, source change
pending producer/consumer validation. No live rootfs mutation, no image build, no
degree-10 local probe.

## The contract being served (from the port's handoff at 55f1c70e)

Order of the subgroup of `O(V)`, `V = L (x) F_p` (rank 10, signature (1,9), det -1024,
even), generated by the 16-17 matrix images of a stabilizer's generators, at p = 5 and
p = 7, as an exact integer, without a BSGS on the natural module (9,765,625 / 282,475,249
points). The port's own acceptance still compares computed against recorded image orders
at {2,3,5,7}; nothing here is a substitute for that.

## What the published image actually contains (measured)

| fact | value |
| --- | --- |
| GAP used by Sage's libgap | system GAP, `4.14.0`, arch `x86_64-pc-linux-gnu-default64-kv9` |
| where libgap gets roots | `sage.libs.gap.util.kernel_info` runs `gap --systemfile`, parses `KERNEL_INFO().GAP_ROOT_PATHS` |
| Debian wrapper roots | `$HOME/gap;/usr/local/lib/gap;/usr/local/share/gap;/usr/lib/gap;/usr/share/gap` |
| packages present | 29, Debian set + polenta-1.3.11 |
| `recog`, `genss`, `forms`, `orb` | absent |

**The Sage spkg route does not reach this GAP.** `build/pkgs/gap_packages/spkg-install.in`
(4.16.1) does list `genss` (line 51), but installs to `PKG_DIR="$SAGE_LOCAL/lib/gap/pkg"`
= `/sage/.venv/lib/gap/pkg`, which is on none of the roots above. `sage -i gap_packages`
here would install files that never load. The port's reading of the spkg list is correct;
the destination is what makes it the wrong route for this image.

**Debian does not package them.** `packages.debian.org` serves an error page with HTTP 200
for `gap-genss`, `gap-recog`, `gap-forms`, `gap-orb`; `sources.debian.org/api/src/<name>/`
returns 404 and `api.ftp-master.debian.org/madison` has no row. So the pinned-tarball route
already used for polenta is the supported one.

## Measured in a sandbox over the image (no rootfs mutation)

Read-only bind of the unpacked image, `/usr/share/gap/pkg` replaced by a copy holding the
four packages; orb built there with `make GAC=.../gac`.

```
LoadPackage(forms) = true     LoadPackage(orb)   = true
LoadPackage(genss) = true     LoadPackage(recog) = true
PackageInfo: genss 1.6.10, recog 1.5.1, forms 1.3.0, orb 5.1.0
GAPInfo.RootPaths includes /usr/share/gap/
LoadPackage("not_a_gap_package") = fail   (error contract for an absent package)
deg2 GF(5) order = 20        in 0.003 s   (nice monomorphism route)
deg4 GF(5) Borel order = 62500 in 0.005 s (= 4*5^6)
sage feature GapPackage('genss') / ('recog').is_present() = True
```

Algorithm contract, from genss's own source and behaviour:

* `StabilizerChain(G, rec(ErrorBound := e))` builds a randomized (Monte Carlo) chain in the
  matrix action; `Size` of that chain is the product of its orbit lengths.
  Measured: deg-4 GF(5) Borel, 3 ms, 62,500 - the exact value.
* genss's `Size` methods apply only to a group with a **stored** stabilizer chain
  (`HasStoredStabilizerChain`), so plain `Size(G)` still goes through
  `grpnice.gd:241` (verified by `ApplicableMethod` before and after loading genss).
* `VerifyStabilizerChainMC(chain, n)` has no method for a plain matrix group
  ("no 1st choice method found"), so the package does not certify exactness here.
* `SizeMC(G, e)` is the direct error-bounded entry point.

**Bounds of this evidence.** Small Borel subgroups only. It shows the packages load in the
instance libgap drives and that a generated matrix subgroup is ordered in the matrix
action; it is not acceptance of the port's generated orthogonal subgroup, and it is not a
proof that a randomized order is exact. A `Size(Borel(10))` probe was run earlier through
the *nice monomorphism* route and did not finish inside 300 s; that is a fact about the
permutation route, not about genss's chain, whose degree-10 behaviour is unmeasured and
belongs to the port's measurement under the shared slot.

## Change made

`docker/research-environment.Dockerfile`: `gap-dev` via apt, then orb/genss/forms/recog
from pinned release tarballs with sha256, extracted into `/usr/share/gap/pkg`, orb's module
built, and a build-time `LoadPackage` gate for all four.
`docker/research-environment-check.py`: asserts the root path the libgap instance reports,
each of the four loading there, `RecognizeGroup` bound, and the deg-4 Borel order through
genss's chain equal to 62,500.
