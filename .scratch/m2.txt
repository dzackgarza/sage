fix: install the research editables outside the project, so they stay checkouts

Run 42255840314's log names the mechanism. The step that reinstalls the research
packages from /repos ran with cwd ${sage_root}, so uv discovered this project's
[tool.uv.sources] and [tool.uv] override-dependencies -- which name every research
package by its git URL so that one resolution can carry the lock -- and those
replaced the path requirements:

    - dzack-research==0.1.1 (from git+.../research@fac3d455)
    + dzack-research==0.1.1 (from git+.../research@e46b96a8)
    - sage-extensions==0.1.0 (from git+...@3a86676f)
    + sage-extensions==0.1.0 (from git+...@d4c75e3b)

while the two packages no source names (pandoc-config, sage-categories-homotopy) did
install from file:///repos. That is why dzack_research imported from site-packages
and nine other modules did not: their names were in the same override list.

Established by dry run against the same uv: from the project directory the command
resolves `dzack-research @ git+...`, from outside it resolves
`dzack-research @ file:///repos/research`. --no-sources does not help, because an
override applies to an -e requirement regardless of sources.

So the install now runs from ${repositories_root}, outside any project, and a
post-condition fails the step if any of those packages did not end up editable,
naming them there instead of an hour later in the environment check.

The check is unchanged: dzack_research stays in its list, the /repos/ prefix stands,
and nothing about the import is optional.
